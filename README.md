# Универсальный парсер презентаций

Мульти-агентная система для извлечения структурированного содержимого презентаций с веб-сайтов.

Система умеет работать как с известными платформами (SlideShare, SpeakerDeck, Google Slides, Prezi и др.), так и с произвольными страницами, где презентация встроена или представлена набором изображений.

---

## Архитектура

Система построена на нескольких специализированных агентах, которые работают через общий буфер на Redis.

### Роли агентов

| Агент              | Количество | Назначение |
|--------------------|------------|----------|
| **Оркестратор**    | 1          | Принимает задание, управляет пайплайном, распределяет подзадачи, следит за состоянием и принимает решения о повторных попытках и обогащении |
| **Сборщик**        | N          | Параллельно собирает сырые данные с сайтов (HTML, скриншоты, изображения, метаданные, вложенные файлы) |
| **Нормализатор**   | 1          | Приводит сырые данные к единой структуре презентации и слайдов |
| **Обогатитель**    | 0–1        | Включается при необходимости. Дополняет данные с помощью распознавания текста и визуального анализа изображений |
| **Агент-хранитель**| 1          | Сохраняет финальный результат и обновляет статус задания |

### Буфер отказоустойчивости (Redis)

Redis используется как надёжный промежуточный слой:

- Очередь подзадач для сборщиков
- Состояние каждого задания
- Промежуточные результаты
- Очередь ошибок (на случай падения агентов)
- Отметки о работоспособности агентов

При падении любого агента задание не теряется — оно возвращается в очередь или уходит в очередь ошибок для последующей обработки.

---

## Как работает система

1. Пользователь передаёт URL презентации (и при необходимости дополнительные параметры).
2. **Оркестратор** создаёт запись о задании в Redis и проводит первичный анализ:
   - определяет платформу;
   - оценивает тип контента (HTML, изображения, встраивание);
   - формирует стратегию сбора.
3. Оркестратор создаёт набор подзадач и кладёт их в очередь.
4. **N сборщиков** параллельно забирают подзадачи, собирают данные и записывают результаты обратно в Redis.
5. Когда все сборщики закончили работу, запускается **Нормализатор**.
6. Нормализатор приводит данные к единой схеме и оценивает полноту.
7. Если данных недостаточно — Оркестратор включает **Обогатителя** (распознавание текста + визуальный анализ).
8. Финальный результат передаётся **Агенту-хранителю**, который сохраняет его и отмечает задание как выполненное.

## Инструменты обогащения

- **ocr.py** — распознаёт текст на изображениях слайдов.
- **vision.py** — с помощью мультимодальных моделей понимает содержимое картинок (графики, схемы, структуру слайда).

Эти инструменты используются Обогатителем, когда обычного HTML недостаточно.

---

## Быстрый старт

```bash
# Запуск Redis
docker-compose up -d redis

# Установка
pip install -e .

# Запуск Оркестратора
python -m workers.start_orchestrator

# Запуск сборщиков (например, 4 штуки)
python -m workers.start_collectors --workers 4
```

### Пример запуска парсинга

```bash
python -m src.main parse --url "https://www.slideshare.net/..." --workers 5
```

## Основные возможности

- Параллельный сбор данных несколькими агентами
- Поддержка динамических и JavaScript-страниц
- Автоматическое обогащение при неполных данных
- Устойчивость к падению отдельных агентов за счёт Redis
- Единая схема вывода (JSON, Markdown, PPTX)
- Расширяемость через адаптеры под конкретные платформы
